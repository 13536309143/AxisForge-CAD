# GLB / OBJ 网格交换

适用版本：AxisForge CAD 0.3.0，2026-11-12。

## 操作入口

- 文件 → **导入 GLB / OBJ 网格…**：追加到当前场景，不替换现有模型，整次导入可以撤销。
- 文件 → **导出 GLB…**：导出全部可见对象，包含 OCCT 实体的显示网格与已导入网格。
- 文件 → **导出 OBJ…**：导出可见对象，同时在同一目录写入配套 MTL 材质文件。
- 文件 → **导出 STL…**：也可以导出网格对象，不保留颜色。
- 命令行传入 `.glb` / `.obj` 路径，也会进入同一导入流程。

导入后可在模型树选择对象，调整名称、颜色、位置、旋转、可见性与固定状态；可直接拖动、复制、删除、撤销和重做。对象局部轴仍可用于当前的同轴、平行、垂直和中心距离配合。

## 实体与网格的区别

导入的 GLB / OBJ 保存为 **网格模型**，不推断它一定闭合，不转换为成千上万个平面组成的伪实体。属性面板的几何尺寸与分段数只读，表面积为三角网格近似值，体积显示“不可用”。

网格能使用四种显示模式。常规模式显示表面；三角面模式叠加剖分边；包围盒模式显示局部盒；网格的线框模式显示三角形边。OCCT 实体的线框仍使用其拓扑边，二者含义有所区别。

**布尔运算只列出 OCCT 实体。** 网格参加核心布尔会被明确拒绝。若可见场景包含网格，STEP 导出失败并说明原因；将网格隐藏后可继续导出其余可见实体。GLB、OBJ 和 STL 可以同时导出实体的显示网格和网格对象。

## GLB 支持范围

实现 glTF 2.0 二进制容器读写，不需要新的第三方运行库。支持：

- 内嵌 BIN、索引／非索引网格；无符号 8／16／32 位索引。
- 三角形、三角带、三角扇；曲线／点图元不在当前范围。
- 连续或交错的属性布局，严格检查 bufferView、accessor 范围、对齐、步长和数量。
- 节点层级、重复实例、TRS 与列主序矩阵，组合父子位姿后展开成对象。
- 非均匀缩放和镜像：烘焙进网格，使用法线逆转置，并修正镜像后的三角形绕序。
- POSITION、NORMAL、对象／节点名称、材质基础颜色；缺少法线时生成平面法线。
- 多 primitive 按独立对象导入，以适配当前每个 Body 一种颜色的数据模型。
- 未指定默认场景时选择第一场景；无场景列表时从节点根开始遍历。

glTF 规定米制和 Y 向上；项目使用毫米和 Z 向上。导入转换为 `(x,y,z)_CAD = 1000 × (x,-z,y)_glTF`，导出执行逆变换。材质基础颜色在线性颜色与项目 RGB 之间转换。导出烘焙对象世界位姿，生成标准 GLB 2.0、表面位置／法线及单色材质。

### 明确的边界

纹理、逐顶点颜色和透明度没有完整保留，会在成功导入后弹窗并写入日志说明；按材质基础颜色／对象单色、不透明显示。动画只采用静态节点变换，并提示未导入动画。

骨骼蒙皮、morph targets、sparse accessor、必需扩展（包括 Draco／Meshopt 压缩）会被拒绝并给出转换建议。外部缓冲、远程 URI 不会被下载。请在源软件中烘焙为静态网格、展开稀疏数据、关闭压缩，再导出 GLB。

GLB 不保留 OCCT 的精确曲面、实体编辑参数、配合和撤销历史。需要继续 CAD 建模请保存 `.afcad`；需要精确实体交换请使用 STEP。

## OBJ / MTL 支持范围

支持 UTF-8 名称／路径、BOM、续行、`v`、`vn`、`vt` 索引、`f`、`o`、`g`、`usemtl` 和 `mtllib`；支持正、负索引及 `v`、`v/vt`、`v//vn`、`v/vt/vn` 面角写法。简单凹多边形用耳切法三角化，不直接使用错误的扇形填充。单个多边形最多 1,024 个顶点；退化和无法三角化的面会拒绝。

OBJ 没有统一的单位／向上轴约定。当前明确按 **mm、Z 向上**处理，不做自动缩放。若其他软件导出的模型大小或朝向不同，应在源软件调整导出选项。将来可在导入对话框增加单位与轴向选项。

MTL 读取 `Kd` 漫反射颜色，多材质对象分成独立网格 Body。当前不保留 UV、纹理贴图、逐顶点颜色、透明材质或平滑组语义；已有顶点法线被保留，缺少时按三角形生成法线。非面元素与被忽略的外观内容通过提示告知。

MTL 只读取 OBJ 同目录下的相对文件，不读取目录外路径或链接。最多读取 32 个材质库、总大小 8 MiB；缺失材质库会提示并使用默认色。导出为 OBJ + 唯一名称 MTL，先提交新材质文件，再原子提交 OBJ，失败时清理新材质。重新覆盖 OBJ 不会覆盖其旧 MTL，以保护失败前的旧文件；旧的未引用材质文件可由用户整理。

**分享 OBJ 时应同时带上它引用的 `.mtl`。** 文件中写有相对 `mtllib` 名称，二者放在同一目录。OBJ 保留名称、法线、世界坐标和对象颜色，不保留 CAD 参数与配合。

## 项目保存与兼容

含网格对象的 `.afcad` 使用 `version: 3`，嵌入压缩的顶点位置和法线，不依赖原 GLB／OBJ／MTL 文件。名称、颜色、位姿、配合及可见性按普通对象保存。旧版程序无法读取 version 3，请使用 0.3.0 或更新版本。

只包含图元与 OCCT 实体的项目仍写为 version 2；当前程序兼容读取 version 1、2、3。压缩载荷读取时检查 Base64、声明解压大小、实际长度、顶点数量、有限数值与退化三角形，失败不替换原场景。

## 资源和失败处理

输入 GLB／OBJ 上限 64 MiB；GLB JSON 上限 16 MiB；导入总量不超过 300 个对象、300 万个提交顶点／100 万个三角形；场景中的网格对象也共同受此顶点预算约束，读取项目时会在解压前检查剩余预算。层级深度最多 64，节点访问有总量限制。坐标要求有限且在 ±1,000,000 mm 范围内。输出 GLB／OBJ 有 64 MiB 上限；大型场景可能需要减少显示细分或分开导出。

读取先构造候选对象，再验证并追加到文档。失败不会留下半个导入结果，也不新增撤销步骤。GLB／OBJ 导出拒绝空可见场景，保护已有文件。限制是资源保护措施，不保证上限规模一定流畅。

## 验证

核心回归覆盖独立 GLB 夹具、单位／轴向、层级／矩阵／镜像、交错属性、三角带／扇、损坏边界、凹 OBJ、负索引、MTL、中文路径、项目兼容与载荷损坏、实体能力边界、失败回滚。桌面检查覆盖文件动作、导入后编辑行为、拖动／删除撤销、四种模式、项目重载和混合场景导出。

本机导出的通孔示例 GLB 另经 Khronos glTF Validator `2.0.0-dev.3.10` 独立检查，结果为 0 error、0 warning。校验器仅用于开发验证，不作为程序运行依赖。

格式依据：[glTF 2.0 官方规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。
